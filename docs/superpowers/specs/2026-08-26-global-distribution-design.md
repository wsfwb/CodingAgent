# Pi 完整版全局分发设计

## 目标

同学获得当前仓库快照后，在 Windows 上运行一次根目录的 `install.ps1`，之后可以在任意工作目录直接执行 `pi`，运行的是当前仓库的完整修改版，包括修改后的 Pi 核心、Plan Mode、Multi-Agent、跨会话长期记忆以及仓库内其他已有改动。

这些功能的接入方式并不相同：跨会话长期记忆等能力已经修改并集成在 Coding Agent 核心中，会随完整工作区构建和全局链接一起生效；Plan Mode 和 Multi-Agent 位于独立工作区包中，还需要写入用户级包配置才能在任意目录加载。它们只是需要额外注册的两个包，不代表完整版本只有两个扩展或只修改了这两处。

本方案不处理自动更新。认证信息、会话历史和长期记忆不随项目分发，由每位使用者自行创建。

## 安装方式

安装脚本以当前仓库为安装源：

1. 检查 Node.js、npm 和必要文件。
2. 在仓库根目录安装依赖并构建所有工作区包。
3. 将 `packages/coding-agent` 通过 npm 全局链接为 `pi` 命令，使修改后的 AI、Agent、Coding Agent、TUI 等工作区代码以及集成在核心中的跨会话长期记忆生效。
4. 将需要额外加载的 `packages/subagents` 和 `packages/plan-mode` 的绝对路径合并到用户级 `~/.pi/agent/settings.json` 的 `packages` 数组。
5. 保留用户已有设置和已有扩展；写入前备份原设置文件。
6. 验证全局 `pi` 命令可解析，且两个扩展路径已经写入配置。

安装完成后，仓库目录必须保留在原位置，因为全局命令和扩展配置引用该目录。移动或删除仓库后需要重新运行安装脚本。

## 错误处理

- 缺少 Node.js 或 npm时立即停止并给出明确提示。
- Node.js 版本低于项目要求时停止，避免产生不可用安装。
- 依赖安装、构建或全局链接失败时停止，不继续写入用户配置。
- 用户配置不是合法 JSON 时停止，不覆盖原文件。
- 配置写入采用临时文件替换，并在修改前保留时间戳备份。

## 使用说明

根目录新增 `README.md`，说明：

- Windows 安装命令仅为 `powershell -ExecutionPolicy Bypass -File .\install.ps1`。
- 首次启动后由使用者自行执行认证并选择模型。
- 可在任意目录执行 `pi`。
- 仓库目录不可随意移动或删除。
- 不会复制项目作者的 API Key、会话或长期记忆。

## 验证

- 对安装脚本中的配置合并逻辑进行隔离测试，使用临时 HOME 目录，避免修改真实用户配置。
- 执行项目构建或相关静态检查。
- 在受控临时 npm 前缀下验证全局链接流程，不覆盖当前机器已有的正式 `pi` 命令。
- 检查全局 `pi` 实际解析到当前仓库构建结果，并验证集成在核心中的修改生效。
- 检查生成的用户配置同时保留旧字段，并只追加缺失的 Plan Mode 和 Multi-Agent 包路径。
